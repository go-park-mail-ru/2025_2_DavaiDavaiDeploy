**Проблемы:**
1. Создание пользователей медленнее чтения в 6 раз - нормально для защищенных операций
   
2. Максимальная задержка до 1.24s при создании - может быть проблемой для UX

3. 93.1% успешных запросов при создании

**Возможные решения:**
1. Добавить индекс для ускорения проверки уникальности логина
CREATE INDEX CONCURRENTLY idx_user_login_lower ON user_table (LOWER(login));

2. При регистрации вместо того, чтобы в методе SignUpUser вызывать метод, который проверяет, есть ли такой юзер, можно сделать так:
INSERT INTO user_table (login, password_hash) 
VALUES ($1, $2)
ON CONFLICT (LOWER(login)) DO NOTHING
RETURNING id;
